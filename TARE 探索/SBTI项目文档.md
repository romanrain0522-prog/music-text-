## 二、核心架构

整个应用分为三个页面（Screen），通过 CSS `display` 切换：

| 页面 | ID | 功能 |
|------|----|------|
| 首页 | `#intro` | 展示标题和"开始测试"按钮 |
| 答题页 | `#test` | 31道题目（含特殊题）的答题界面 |
| 结果页 | `#result` | 展示人格类型、匹配度、维度分析 |

### JavaScript 核心数据结构

所有数据均以 JavaScript 对象/数组的形式定义在 `<script>` 标签内：

| 变量名 | 类型 | 说明 |
|--------|------|------|
| `dimensionMeta` | Object | 15个维度的元信息（名称、所属模型） |
| `questions` | Array | 30道常规题目 |
| `specialQuestions` | Array | 2道特殊题目（饮酒筛选） |
| `TYPE_LIBRARY` | Object | 26种人格的详细信息（代号、中文名、介绍、描述） |
| `TYPE_IMAGES` | Object | 人格对应的配图路径 |
| `NORMAL_TYPES` | Array | 25种常规人格的模式匹配向量 |
| `DIM_EXPLANATIONS` | Object | 15个维度在 L/M/H 三级下的解释文本 |
| `dimensionOrder` | Array | 维度计算顺序 |

## 三、十五维度体系

SBTI 采用 **15个维度 × 3个等级** 的评分体系，分为5大模型：

### 3.1 自我模型（Self）

| 维度 | 名称 | 含义 |
|------|------|------|
| S1 | 自尊自信 | 对自我价值的认同程度 |
| S2 | 自我清晰度 | 对真实自我的认知程度 |
| S3 | 核心价值 | 对成长和目标的追求程度 |

### 3.2 情感模型（Emotion）

| 维度 | 名称 | 含义 |
|------|------|------|
| E1 | 依恋安全感 | 感情中的安全感和信任程度 |
| E2 | 情感投入度 | 对感情的投入和认真程度 |
| E3 | 边界与依赖 | 对个人空间和独立性的需求 |

### 3.3 态度模型（Attitude）

| 维度 | 名称 | 含义 |
|------|------|------|
| A1 | 世界观倾向 | 对世界和人性的基本态度 |
| A2 | 规则与灵活度 | 对规则的遵守或打破倾向 |
| A3 | 人生意义感 | 对人生目标和意义的感知 |

### 3.4 行动驱力模型（Action）

| 维度 | 名称 | 含义 |
|------|------|------|
| Ac1 | 动机导向 | 追求成果 vs 避免风险 |
| Ac2 | 决策风格 | 果断程度 |
| Ac3 | 执行模式 | 行动力和计划性 |

### 3.5 社交模型（Social）

| 维度 | 名称 | 含义 |
|------|------|------|
| So1 | 社交主动性 | 主动社交的意愿 |
| So2 | 人际边界感 | 与他人亲近或保持距离的倾向 |
| So3 | 表达与真实度 | 在不同场合表现的一致性 |

## 四、评分规则详解

### 4.1 题目结构

每道常规题目包含：
- `id`：唯一标识（q1 ~ q30）
- `dim`：所属维度（S1, S2, ..., So3）
- `text`：题目文本
- `options`：3个选项，每个选项有 `label`（文本）和 `value`（分值 1/2/3）

### 4.2 分值计算

每个维度的原始分数 = 该维度下所有题目选项分值之和。

每个维度有 **2道题目**，每题分值 1~3，因此：
- **最低分 = 2**（两题都选1）
- **最高分 = 6**（两题都选3）

### 4.3 等级划分

原始分数通过 `sumToLevel()` 函数转换为等级：

| 原始分数 | 等级 | 含义 |
|----------|------|------|
| ≤ 3 | **L**（Low） | 低 |
| = 4 | **M**（Medium） | 中 |
| ≥ 5 | **H**（High） | 高 |

### 4.4 人格匹配算法

1. **构建用户向量**：将15个维度按 `dimensionOrder` 顺序排列，将 L/M/H 转换为数值（L=1, M=2, H=3），得到15维向量
2. **计算距离**：对每种人格类型的模式向量，计算与用户向量的曼哈顿距离（各维度差值绝对值之和）
3. **计算匹配度**：`similarity = max(0, round((1 - distance / 30) * 100))`
4. **排序**：按距离升序 → 精准命中数降序 → 匹配度降序排列
5. **特殊判定**：
   - 如果饮酒触发题选择了"习惯将白酒灌在保温杯" → 直接判定为 **DRUNK（酒鬼）**
   - 如果最高匹配度 < 60% → 强制分配为 **HHHH（傻乐者）**

### 4.5 模式向量示例

每种人格由一个15位的模式字符串定义，例如：

```
CTRL:  HHH-HMH-MHH-HHH-MHM
ATM-er: HHH-HHM-HHH-MMH-MHL
Dior-s: MHM-MMH-MHM-HMH-LHL
```

每一位对应一个维度（按 dimensionOrder 顺序），值为 H/M/L。

## 六、特殊题目机制

除了30道常规题目外，还有 **2道特殊题目**，随机插入在答题序列中：

### 饮酒筛选题（drink_gate_q1）
> "您平时有什么爱好？"
> - 吃喝拉撒（value: 1）
> - 艺术爱好（value: 2）
> - **饮酒（value: 3）** ← 触发下一题
> - 健身（value: 4）

### 饮酒触发题（drink_gate_q2）
> "您对饮酒的态度是？"
> - 小酌怡情，喝不了太多。（value: 1）
> - **我习惯将白酒灌在保温杯，当白开水喝，酒精令我信服。（value: 2）** ← 触发酒鬼人格

**逻辑**：只有当第一题选择"饮酒"时，才会显示第二题；第二题选择"保温杯灌白酒"时，最终结果强制为 DRUNK（酒鬼），跳过常规匹配。

## 七、自定义指南：如何修改题目和人格

> **核心原则**：所有自定义工作都在 `index.html` 文件的 `<script>` 标签内完成。

### 7.1 自定义题目

需要修改的变量：**`questions`**（第802行附近）

#### 修改现有题目

```javascript
{
  id: 'q1',           // 题目唯一ID（不可重复）
  dim: 'S1',          // 所属维度（必须是 dimensionMeta 中定义的维度）
  text: '你的新题目文本',
  options: [
    { label: '选项A文本', value: 1 },  // value: 1=低, 2=中, 3=高
    { label: '选项B文本', value: 2 },
    { label: '选项C文本', value: 3 }
  ]
}
```

#### 添加新题目

1. 在 `questions` 数组中新增一个对象
2. 确保 `id` 不与已有题目重复
3. `dim` 必须是已有的维度代号
4. **注意**：每个维度目前有2道题，添加新题会改变该维度的最高分，需要同步调整 `sumToLevel()` 函数的分值阈值

#### 删除题目

直接从 `questions` 数组中移除对应对象即可。注意删除后对应维度的题目数量减少，可能需要调整评分阈值。

### 7.2 自定义人格

需要修改的变量：**`TYPE_LIBRARY`**（第1099行附近）

#### 添加新人格

```javascript
"NEWCODE": {
  "code": "NEWCODE",       // 人格代号（大写字母+符号）
  "cn": "中文名",           // 人格中文名
  "intro": "一句话介绍",    // 结果页的海报配文
  "desc": "详细描述文本"     // 人格的完整解读
}
```

#### 修改现有人格

直接修改 `TYPE_LIBRARY` 中对应 key 的 `cn`、`intro`、`desc` 字段即可。

### 7.3 自定义人格匹配模式

需要修改的变量：**`NORMAL_TYPES`**（第1293行附近）

每种人格需要一个15位的模式字符串，对应15个维度的 H/M/L 等级：

```javascript
{
  "code": "NEWCODE",
  "pattern": "HHH-HMH-MHH-HHH-MHM"  // 15位，用-分隔
}
```

**模式设计建议**：
- 每个位置对应 `dimensionOrder` 中的一个维度
- 顺序为：S1 S2 S3 - E1 E2 E3 - A1 A2 A3 - Ac1 Ac2 Ac3 - So1 So2 So3
- 每位值为 H（高）、M（中）、L（低）

### 7.4 自定义人格配图

需要修改的变量：**`TYPE_IMAGES`**（第1263行附近）

```javascript
"NEWCODE": "./image/NEWCODE.png"
```

将对应的图片文件放入 `image/` 文件夹即可。

### 7.5 自定义维度解释

需要修改的变量：**`DIM_EXPLANATIONS`**（第1395行附近）

```javascript
"S1": {
  "L": "低分时的解释文本",
  "M": "中分时的解释文本",
  "H": "高分时的解释文本"
}
```

### 7.6 自定义特殊题目

需要修改的变量：**`specialQuestions`**（第1074行附近）

结构与常规题目类似，但额外包含：
- `special: true` — 标记为特殊题目
- `kind` — 特殊题目类型（如 `drink_gate`、`drink_trigger`）

### 7.7 自定义维度体系

需要修改的变量：**`dimensionMeta`**（第785行附近）和 **`dimensionOrder`**（第1472行）

```javascript
// 1. 在 dimensionMeta 中添加新维度
const dimensionMeta = {
  // ...已有维度
  "X1": { name: 'X1 新维度名', model: '新模型' }
};

// 2. 在 dimensionOrder 中添加新维度（注意顺序）
const dimensionOrder = ['S1','S2','S3','E1','E2','E3','A1','A2','A3','Ac1','Ac2','Ac3','So1','So2','So3','X1'];

// 3. 同步更新：
//    - DIM_EXPLANATIONS 中添加 X1 的 L/M/H 解释
//    - questions 中添加对应 X1 的题目
//    - NORMAL_TYPES 中每个 pattern 末尾添加一位
```

### 7.8 修改评分阈值

如果改变了每个维度的题目数量，需要修改 **`sumToLevel()`** 函数（第1587行）：

```javascript
function sumToLevel(score) {
  // 默认：每维度2题，每题1-3分，总分2-6
  if (score <= 3) return 'L';
  if (score === 4) return 'M';
  return 'H';
}
```

如果改为每维度3题（总分3-9），可以调整为：
```javascript
function sumToLevel(score) {
  if (score <= 4) return 'L';
  if (score <= 6) return 'M';
  return 'H';
}
```

## 九、注意事项

1. **所有修改都在 `index.html` 一个文件中完成**，无需构建工具
2. 修改后直接用浏览器打开 `index.html` 即可预览
3. 题目在每次测试时会**随机打乱顺序**（`shuffle()` 函数）
4. 特殊题目（饮酒筛选）会**随机插入**到常规题目中
5. 匹配算法使用**曼哈顿距离**，最大距离为30（15个维度 × 最大差值2）
